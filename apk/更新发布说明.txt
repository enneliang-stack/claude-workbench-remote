Claude 工作台 · 双模式 APK 更新发布
====================================

App 的「设置与日志 → 检查更新」读取本仓库 apk/update.json，直连失败时会尝试镜像：
https://raw.githubusercontent.com/enneliang-stack/claude-workbench-remote/main/apk/update.json

日常发布只更新精简包。已安装手机端环境的用户在 App 内检查更新即可。首次安装或尚未安装环境时使用清单指向的完整包，安装环境后再更新精简包。当前完整包基线为 v2.4.150（versionCode 191）。完整包下载地址固定到该版本的 Release 标签。

1. 增加 AndroidManifest.xml 的 versionCode 和 versionName。改动手机内置网页或本机资源时，同时递增 LocalEngine.java 的 ASSET_VERSION。
2. 运行 SLIM=1 bash android/app/build.sh。核对 APK 的版本、SHA-256 和签名证书；签名必须与上次发布一致，才能让 Android 覆盖安装。
3. 将精简 APK 暂存到 apk/release/ClaudeWorkbench-slim.apk，并同步本机运行目录 claude-gui/apk/ClaudeWorkbench-slim.apk。
4. 更新 README.md 的最新 APK 信息及 apk/update.json 的 versionCode、versionName、slimApk、slimSha256 和 notes。slimApk 指定本次 Release 的版本标签及固定资产名，使清单缓存始终对应同一份 APK。日常更新保留完整包的 apk、sha256、fullVersionCode 和 fullVersionName。
5. 新建 v版本号 Release，上传固定资产名 ClaudeWorkbench-slim.apk。确认发布后可下载，再推送 main 分支的更新清单，核对公开资产与清单的摘要一致。APK 通过 Releases 分发。
6. 普通更新的 important 为 false。需要在手机 App 主页主动提示的重要更新设为 true。

只有在刷新新用户环境基线或明确要求时才构建完整包。运行 bash android/app/build.sh 后，以 ClaudeWorkbench-full.apk 上传到该版本 Release，再更新 apk/update.json 的完整包字段。完整包超过 GitHub 普通文件的 100 MB 上限。

本地构建完整 APK 前需要准备（这些大文件不进 git）：
- phone/claude-musl.tgz：Claude Code linux-arm64-musl 的 npm 包
  （@anthropic-ai/claude-code-linux-arm64-musl，约 144 MB）
- phone/offline-apk/*.apk：运行 python phone/fetch-offline-packages.py 生成
- phone/alpine-minirootfs-3.24.2-aarch64.tar.gz：同脚本自动下载

生成后运行 android/app/build.sh 即可得到内置完整环境的 APK。
